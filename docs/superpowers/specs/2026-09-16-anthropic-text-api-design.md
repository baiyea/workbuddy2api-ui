# Anthropic 文本接口与双协议控制台设计

日期：2026-09-16

状态：总体方案和 visualize 交互原型已获用户确认；本文件待实施前审阅。本文不是实现完成记录。

## 1. 目标与边界

为 WorkBuddy / CodeBuddy 网关增加 Anthropic Messages 文本协议入口，同时保持现有 OpenAI 接口的行为与接入方式不变。第一版验收对象是普通文本、多轮对话和流式响应，不是实际 Claude Code 客户端或完整编程代理。

- 共用现有 API Key、模型 ID、账号池、上游客户端和账号调度逻辑。
- 模型保留 `cn:` / `global:` 前缀，不增加模型别名或单独维护模型目录。
- 所有现有模型均可尝试通过新接口进行文本调用；实际可用性与能力仍由上游决定。
- 不支持工具调用、图像、文件、扩展思考、缓存控制及其他高级 Anthropic 功能。
- 不增加第三个服务、运行时依赖、数据库、协议自动探测或隐式删参数重试。
- 保持两个容器、一条 `docker compose up -d` 启动、既有存储与密钥机制。
- 不修改上游快照，不为历史版本增加迁移或兼容机制。

## 2. 架构选择

推荐在 core 扩展层增加专用协议适配器。相比放进 console，它保持业务职责集中；相比独立代理容器，它不增加部署和维护环节。

```text
console /v1/chat/completions ────────────────────┐
                                               ▼
                                      现有 OpenAI Handler
                                               │
console /v1/messages → core 文本协议适配器 ──────┘
                                               │
                                      现有账号池及上游客户端
                                               │
                                      WorkBuddy / CodeBuddy
```

适配器只截获新端点。将请求转换后在进程内调用既有公共 Handler，转换其普通或流式响应；不另发本机 HTTP 请求，不复制选号、重试、计费或会话逻辑。

在 `extensions/cmd/server/extension.go` 的现有接线处组合适配器与原 Handler，桥接接口使用组合后的公共入口。新增实现与测试放在 `extensions/internal/anthropic/`。预计无需增加上游补丁；若实际发现必须改变上游行为，应先说明原因和范围，不暗中扩展设计。

console 的公共 `/v1/` 代理继续使用原有机制。网页测试通过新增受保护的管理路由进入同一个适配器，不在浏览器中暴露桥接密钥，不单独实现另一套转换。

## 3. 请求契约

新端点：`POST /v1/messages`。

- 公共请求使用 `x-api-key`，值为现有模型调用 API Key；管理密钥与桥接密钥不能调用该公共入口。
- 版本头使用 `anthropic-version: 2023-06-01`。缺失或不支持的版本明确报错，不宣称支持任意版本或 beta。
- 第一版必需字段为 `model`、正整数 `max_tokens`、非空 `messages`；可选字段为 `system`、`stream`。
- `system` 接受字符串或纯文本内容块，转换为现有请求中的 system 消息；`messages` 仅接受 user / assistant 角色，content 接受字符串或纯 text 内容块。
- `stream` 缺省为 false。API 不为缺失的 `max_tokens` 静默补值，网页显式提交默认值 1024。
- 首版仅承诺上述最小字段集合。`stop_sequences`、采样参数、工具、思考、缓存、beta 等未支持字段明确返回参数错误，不仅删除后继续请求。
- 网页既有会话关联信息通过受保护的管理接线保留；公共 API 不因此增加必须的私有字段。
- 请求体大小沿用现有配置上限，在读取转换前限制；转换后的请求也必须满足现有 Handler 上限。

新端点按自身协议校验认证和字段。不得全局修改原 OpenAI 鉴权、请求解析或响应处理。

## 4. 响应与错误

普通响应返回 Messages 文本结构：消息 ID、`type: message`、`role: assistant`、`content` 文本块、模型、停止原因和用量。

- 普通结束映射为 `end_turn`，输出长度限制映射为 `max_tokens`。
- 上游工具输出、无法安全解释的结束原因或畸形数据不能伪装成正常文本成功，应明确返回适配错误。
- 模型信息保留网关路由身份；不把非 Claude 模型伪装成 Claude。
- 只映射上游实际返回的 token 数，不自行估算。未知用量保持未知，UI 显示“上游未返回用量”。
- 对未知用量采用明确的兼容子集约定：缺失的 token 字段为 `null`，不是真实的 0；文档须说明这与原生 API 的整数用量字段存在差异。不得承诺依赖严格整数校验的所有客户端均可用。
- SDK 验收覆盖已知和缺失用量，验证目标官方 SDK 的文本消费与最终消息聚合；如果不能满足，先调整并审阅该契约，不能用伪造 token 数换取测试通过。

流式按 Anthropic 事件顺序逐步输出：`message_start` → `content_block_start` → `content_block_delta` → `content_block_stop` → `message_delta` → `message_stop`。不能先缓存完整回答再拆成流。

初始未知用量为 null，后续取得实际值时更新；最终用量是累计值，不重复相加。正常完成要求得到可信的结束原因；不能仅凭原 Handler 补出的 `[DONE]` 判断成功。

适配器正确处理跨 Write 分片、UTF-8、空块、错误事件和连接中断。开始响应前使用 HTTP 错误与 Anthropic 错误包；开始 SSE 后使用 error 事件并终止，不再发送正常完成事件。客户端取消或写入失败应取消底层请求，避免悬挂 goroutine 或继续消耗模型调用。

错误文案保留可操作信息，不输出账号凭据、内部密钥或未脱敏的上游原始响应。

## 5. UI 定稿

沿用当前控制台导航、字体和绿色视觉风格，只修改“API 接入”和“对话测试”。以本次用户确认的 visualize 原型为布局与交互参考，不把原型的模拟调用实现带入业务代码。

### API 接入

- 顶部 OpenAI / Anthropic 分段切换，首次进入默认 OpenAI。
- 两种协议共用 API Key 的显示与复制能力，不能复制为管理登录密钥。
- 展示客户端 Base URL、完整请求端点、鉴权方式、模型选择和可复制 curl 示例。
- OpenAI 保持现有 `/v1` Base URL；Anthropic 示例使用服务根地址，并说明所示客户端会追加 `/v1/messages`，避免重复拼接路径。
- 示例随协议及模型变化，保留前缀；没有可用模型时明确提示，不将原型中的 `your-model-id` 当作真实模型。
- Anthropic 模式显示“文本兼容”范围和限制，不写“完整支持 Claude Code”。
- “前往对话测试”携带当前协议与模型，不新建页面或标签页。

### 对话测试

- 在原有页面增加同样的协议选择，默认 OpenAI；保留现有模型选择和消息展示。
- Anthropic 模式显示最大输出 tokens，默认 1024；隐藏不支持的推理档位。
- 使用真实的新协议请求和 SSE 解析，不只切换标签或复用 OpenAI 响应假装验证成功。
- 切换协议清空当前测试对话；生成期间禁止协议切换、模型切换和清空。
- 保留发送、停止生成、多轮对话和错误提示；未知用量显示未知。
- 流式更新不抢夺键盘焦点；按钮有可访问名称，结果状态可被辅助技术读取。
- 移动端将字段纵向排列，无横向溢出。复用既有页面测试，不引入前端框架。

原型中的演示密钥、示例模型、模拟回答和设计调节项仅用于沟通，不是最终产品功能。

## 6. 验证与交付

新增逻辑先写失败用例，再实现最小转换。验证范围：

1. 请求：system / 文本块 / 多轮 / 模型前缀 / stream / max_tokens；鉴权、版本头、非法字段、请求超限；非法请求不进入账号调用链。
2. 响应：普通文本、长度终止、已知与缺失用量、非法上游数据；流式分片、实时首片、事件顺序、中断、空流、取消和流内错误。
3. 隔离：原 OpenAI 请求绕过新转换，原有测试继续通过；两个协议进入同一个账号池与转发链路。
4. 管理：网页新测试路由保留会话、CSRF、同源与桥接认证，公共调用不能绕过认证。
5. 客户端：在隔离环境固定一个官方 Anthropic SDK 版本，验证普通文本、流式迭代与最终消息聚合；SDK 仅作验证工具，不加入生产镜像运行依赖。
6. UI：协议切换、地址与示例更新、模型传递、清空、停止、禁用态及错误展示；桌面和窄屏真实页面检查。
7. 集成：`bash scripts/check.sh`，再用隔离的 mock 环境运行 `bash scripts/acceptance.sh`，不接触真实账号或生产容器。

真实模型验证与模拟验收分开报告。未获授权不得消耗真实账号或宣称实际 Claude Code 可用。

更新 README 的功能、接入示例和限制，更新 AGENTS 的架构入口。预计工作量为熟悉代码的开发者 3～5 人日，非承诺工期。

本设计确认后先编写实施计划；不自动更新上游、推送 Git、发布镜像或重启现有服务。当前文档步骤不改 Compose 镜像标签。
