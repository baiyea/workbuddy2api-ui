# Docker 一键启动与 Web 控制台

## 目标与交付边界

在拿到本项目源码和 Compose 文件、服务器已安装 Docker Compose 且网络可达的前提下，执行 `docker compose up -d`，即可访问 `http://服务器地址:7863/`。首次启动自动准备持久化目录和管理凭据；此后添加账号、等待授权、查看状态、测试回答均在网页完成。

自动化指网关发起授权、轮询结果、保存凭据、加载账号、查询状态。上游页面要求的账号登录、扫码、验证码及授权确认，由用户在自己的浏览器完成。容器不运行浏览器，不收集上游密码。

本次在当前工作目录实现，不创建 worktree。保留已有 CLI 用法和 `/v1` 协议。实现与本地构建属于本次范围；推送镜像到某个外部仓库、部署到实际服务器需要已知目标和相应权限，不能把第三方已发布镜像当作包含本次修改的产物。

## 方案选择

1. **采用：Go 内置静态网页，单服务、单端口、一个镜像。** Go 标准库提供 HTTP 和静态资源嵌入；页面使用原生 HTML/CSS/JavaScript。复用现有账号池、模型列表和聊天处理器。
2. 独立前端服务或独立聊天应用：已有 UI 能力多，但增加部署单元，而且不能直接解决本项目账号授权和状态管理，因此本次不采用。

## 部署与初始化

- 默认 Compose 保留源码构建能力，首次 `up -d` 在本地镜像不存在时构建，随后启动。无需先复制配置、运行登录脚本或手工创建目录。
- 镜像具备网页、Go 服务和原有后台任务所需运行时。排除 `.agents`、开发产物及真实凭据等无关构建内容。
- 默认使用 Docker 命名卷分别保存 `/app/auths` 与 `/app/data`；镜像中的目录预置给 UID 10001，应用保持非 root 运行。旧 bind mount 用户按 README 显式接回原路径，不能静默覆盖或迁移原数据。
- 默认启动不使用示例 `test_key`。镜像启动模式自动生成并持久化相互独立的管理员密钥和 API Key；已有配置的 API Key 优先，管理功能仍单独鉴权。
- 默认管理员密钥从容器日志获得后输入网页；也允许部署者通过环境变量预设管理员密钥。自动生成的密钥保存在数据卷中，重启不变化。这个方案需要首次查看一次容器日志，不宣称全过程只有一条操作命令。
- 管理登录页面明确告知如何取得密钥；不提供无鉴权的“第一个访问者成为管理员”入口。环境变量预设可省去首次查看日志。
- 新增存活检查供 Docker 使用，空账号池也应显示服务已启动。保留 `/healthz` 的账号可服务性语义，在网页中区分“程序运行中”和“尚无可用账号”。
- 沿用多架构发布流程，构建 `linux/amd64`、`linux/arm64`。发布版 Compose 可以通过明确镜像地址使用已发布产物，源码版不能默认拉取不含本次改动的上游 `latest`。

## Web 页面

使用中文界面，适配桌面和手机；页面和资源本地提供，不依赖 CDN。

### 管理登录

输入管理员密钥后建立有期限的 HttpOnly、SameSite 会话 Cookie；HTTPS 下设置 Secure。退出清理会话。写操作校验同源和 CSRF，登录与授权创建限速，管理员密钥不进入 URL 或浏览器持久化存储。反向代理使用 HTTPS 时遵循明确配置，不无条件信任任意客户端传来的代理头。

### 概览与账号

展示总账号数、可用数、冷却数、禁用数、当前在途请求数，以及每个账号的昵称、所属版本、积分、限流模型、冷却截止时间、成功/错误计数。复用现有 `/status` 数据结构。

状态数据注明是本地最近一次观测，积分未知不显示成已确认的零余额。提供刷新状态、添加账号及重新授权；首版不添加删除账号和任意编辑配置功能。

### 添加账号

1. 用户选择国内版或国际版，点击开始授权。
2. 后端创建独立、短时有效的登录流程，返回流程 ID 和上游授权链接；上游 state 留在服务端。
3. 网页打开授权页面，并保留可点击链接作为浏览器阻止弹窗时的后备入口。
4. 网页自动查询登录进度，后端按限频规则检查上游 token 和账号资料，页面显示等待、完成、需补充资料、过期或失败。
5. 获取完整凭据及合法 UID 后，复用 `Auth.SaveAtomic` 原子保存，保存成功才加入现有账号池。新账号无需重启即可调用；同账号重新授权更新凭据并解除登录失效导致的禁用，不擅自清除其他模型限流。
6. 国内版同步尝试现有签到和积分查询；附属任务失败不会抹掉成功的登录结果。
7. 国际版复用已有注册/地区完善语义和 trial 能力：已完善的账号直接继续；需要地区时从上游允许列表展示选项，由用户选择后提交。不得自动编造或替用户选择地区。激活或 trial 失败分别展示原因，保留已获得的账号凭据并允许重试。

从现有 `cmd/login` 中提取最小共享 OAuth 客户端，CLI 和 Web 复用协议实现。Web 不执行 `login.sh`，不使用共享 `/tmp/wb2api-login-state.json`，不向容器挂载 Docker socket。

每个流程保存独立的 state、realm、HTTP cookie jar、有效期与状态；绑定发起的管理员会话。流程最多保留 10 分钟，限制同时进行的流程数并清理过期数据。并发轮询不能重复交换凭据、重复写文件或重复领取奖励。退出后不能继续操作旧流程。上游失败需区分明确的未授权状态、会话过期、协议错误和临时网络故障，不把所有错误当作等待。

### 对话测试与 API 接入

- 展示模型选择、推理档位（模型支持时）、输入框、流式回答、停止生成及清空会话。
- 根据模型列表和账号所属版本提示哪些模型当前有对应账号；静态模型列表不等于该账号已通过真实调用验证。
- 每次提交携带当前测试会话的消息历史及稳定的会话 ID，复用现有路由与推理参数适配。停止时取消 HTTP 请求并释放上游请求占用。
- 回答、推理内容和工具调用按纯文本安全呈现；首版不在服务器执行模型返回的工具调用。
- 展示上游实际返回的 usage 和错误信息；缺失用量显示未知。
- API 接入区提供 Base URL、显式点击后展示/复制的 API Key 和简单请求示例。API Key 不直接注入静态资源或 HTML。
- 对话只保存在当前页面内存中，刷新后清空；不提供跨重启的聊天历史和任务流水数据库。

## 后端边界与兼容

- 新增 `/admin/` 下的管理会话、授权流程、账号状态、模型、测试聊天及接入信息端点。管理请求通过管理员会话校验，内部复用既有业务方法，不让管理员 Cookie 自动成为公共 `/v1` 的凭据。
- 静态首页可匿名加载；账号数据、API Key、授权动作和测试聊天必须鉴权。现有 `/status` 与 `/v1` 仍使用原有 Bearer API Key。
- 上游 access/refresh token 不回传浏览器，不写入业务日志；上游错误对外返回可理解的摘要，避免泄露凭据。授权链接属于短期敏感信息，禁止写入普通请求日志。
- 限制入站请求与上游响应大小，严格验证 realm、流程 ID、UID 和地区选择；UID 不能形成目录穿越。只调用受控上游地址，授权链接校验 HTTPS 和可信域名，防止任意跳转或 SSRF。
- 凭据保存与同账号刷新协调，避免旧的在途请求把刚重新授权的凭据覆盖回去。保持其他账号正在处理的请求不受影响。
- 修改尽量限定在 OAuth 共享代码、管理 HTTP 与静态资源、入口接线以及部署文档；不重构账号池调度算法。

## 验收

1. 全新命名卷、没有 config.json 或账号文件时，只执行 `docker compose up -d` 即能访问中文管理登录页，容器存活检查通过。
2. 未登录无法读取账号、API Key、创建或轮询授权、执行聊天；错误密钥、跨站写请求被拒绝。
3. 使用模拟上游验证授权等待、完成、过期、网络故障、资料缺失、并发轮询与重复授权；日志及响应不出现上游令牌。
4. 国内版授权完成后自动显示账号，无需重启即可通过网页进行流式、多轮和停止生成测试。
5. 国际版需要地区时可在网页选取并完成激活；网络或 trial 失败有可恢复的明确提示，不伪报“账号可聊天”。
6. 容器重启和重建后，账号及管理凭据仍可使用；旧 CLI、API Key 接入与已有账号文件兼容。
7. 运行现有 Go 测试与受影响代码的竞态检查，构建镜像，实际打开容器网页验证核心流程；模拟上游覆盖自动验收。真实上游登录和真实模型回答使用用户本人账号验收，遇到人机验证时由用户完成，不能以模拟测试宣称真实调用通过。
8. 交付记录包含启动命令、端口、管理凭据取得方式、数据卷位置、构建/测试结果，以及尚需真实账号或发布目标才能完成的项目。

## 明确不包含

多用户权限体系、收费计费、独立前端服务、通用 Agent 工具执行、自动代答验证码、历史聊天数据库、任务管理平台、额外浏览器容器及对外发布到未指定的镜像仓库。
